Every AI invocation — request, decision, application, error — lands here as an append-only event with model + actor + provenance. The same store backs the F9.6 invocation log (rejected suggestions are kept as evidence) and the F9.7 audit-trail export. Local-only, never deletable.

Suggestion surfaces

These F-features are wired in their natural location. The dashboard view that aggregates pending suggestions across the project will graduate here as F8.6 + F8.7 land their UI.

  • Suggest existing code on a span (F8.3) — open a transcript and use the "✨ Suggest existing code with AI" row in the apply-popover on a highlight.
  • Propose a new code on a span (F8.4) — separate command in the apply-popover: "✨ Propose a new code with AI". Picking a proposal creates the :class:`Code`, applies it to the span, and stamps AI provenance (feature=new_code_suggestion). Pending and rejected proposals are kept as audit rows under /ai/new-code-suggestions per F9.6.
  • Find similar quotes (F8.5) — per-application action on the source-coding view: open a transcript with at least one coded segment and click the "🔎 Find similar quotes" button on any .app-row. The ranked list comes back from POST /ai/quote-searches and is logged for the F9.6 audit trail. No LLM call — pure embedding-space nearest-neighbour search over the F8.2 index, so this is the safest of the AI features.
  • Whole-transcript review pass (F8.6) — open any source's coding view and click "✨ Review whole transcript" in the page actions. The pass walks every paragraph (or sentence, with the granularity dropdown), produces one pending CodeSuggestion per span, and surfaces them in the modal with Accept / Reject buttons. Pass state is persisted to review_passes/<rpid>.json so a refresh resumes where the worker left off, and the F9.6 audit log records the invocation.
  • AI second coder (F8.7) — once the codebook is locked (F2.4), the AI re-codes a transcript in parallel with a designated human coder and computes Cohen's kappa (F2.5) over the diff. Use the Second-coder pass card below to start a pass and review per-code agreement.
  • Memo drafting (F8.8) — open the codebook editor, pick a code, and click "✨ Draft memo with AI" to seed a first-draft analytic memo from the code's exemplars and applications. The draft lands as a pending record under /api/projects/<pid>/memo-drafts; saving promotes it into a Memo with provenance source=ai_drafted; rejecting still records the invocation per F9.6. The Memo drafts card below lists every draft across the project.
